# Review report writing

Apply this policy to prose you author for review artifacts, configuration proposals and their delivery summaries. Keep the caller's purpose, reader, length and destination settings; `explain-to` still owns audience and output choices.

## Resolve repository preferences

Reuse writing preferences from the current request and existing setup/configuration outputs. A supplied review profile, otherwise `.nthplusio-skills/review.json`, can point to those outputs through `guidance`. Read the referenced files; do not treat a checklist category as a writing preference. Repository guidance may disable either pass or select a declared project voice. Omitted preferences use both passes when available, in the order below. Do not require setup to write a report.

## Edit prose before formatting

1. Load and apply `speak-clearly`, if available and enabled, to make the draft clear and concise.
2. Then load and apply `writing-in-voice`, if available and enabled, to personalize that clarified draft. Resolve the intended speaker's profile using that skill's selection and privacy rules. The report's reader is not automatically its speaker; another reviewer's voice is not the current user's voice.

Use only enabled, available passes, preserving their order when both run. Missing helpers do not block delivery or require installation. Without a usable voice profile, use explicitly supplied session preferences or keep clear neutral prose and briefly disclose the limitation. Do not invent a voice, require an interview or create/save a profile just to finish a review. Never copy a personal profile, private samples or personal-provider contents into repository guidance, report evidence or a reusable skill.

Apply these passes to authored summaries, explanations, captions and next actions, not original review bodies, requirement quotes, source excerpts, code, commands, links or technical identifiers. Preserve verdicts, severity, criterion-level results, ownership, timestamps, uncertainty, accepted gaps and evidence limits. A friendlier voice cannot turn missing evidence into verification or soften a blocker into a pass.

Format the edited prose for the chosen document or HTML destination without changing its meaning. Compare the final prose with the source evidence before delivery; repair any changed claim without restarting a cycle of style passes. Record a skipped pass only when it affects the requested result; keep process notes out of the report's main narrative. Style edits grant no publication or profile-write authority.
